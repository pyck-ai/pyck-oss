# pyck

Org-wide rules: `~/.pyck/guidelines/AGENTS.md`. They apply here; this file adds only local facts. If that path is missing, ask the user to install pyck-ai/guidelines (clone it and run its `setup.sh`); never fetch the rules from the web.

## Commands

- `task lint:commits`: run before pushing. CI enforces [docs/COMMIT_STANDARDS.md](docs/COMMIT_STANDARDS.md), a stricter local check than the org git guideline (subject max 50 chars, hard fail). It is deliberately not part of `task lint`.
- `task generate`: after any change under `ent/schema/`, `*.graphql` or a `go:generate` directive. Regenerates `ent/gen/`, `model/*_gen.go` and the supergraph; commit the output.
- `task atlas:migrate -- <name>` (in `backend/<service>/`): after an `ent/schema/` change, to write the migration into `ent/migrate/migrations/`. `task check:drift` runs the same drift check as CI.
- `task test:slow` (in `backend/<service>/`): the `_Slow$` tests that `task test` skips with `-short`; CI runs them on main and nightly.
- `task test:integration`: needs `task up:integration` (fast cadences). `task test` never runs these suites.
- `task local-setup`: wipes `config/keys/*` and needs a fresh Zitadel database; prefer `task up`, which is safe to repeat.
- `task container:up|debug|logs`: in `backend/<service>/` for one service, at the root for all; there is no `task run`.

## Before you change

- A suite that needs a live stack (gateway, Zitadel, Temporal): read `tests/integration/AGENTS.md` first; unit tests stay in `backend/<service>` with testcontainers.
- Tenant headers, roles or disabled-tenant behaviour: read `docs/tenant-access-control.md`.
- Service shutdown order or stop grace periods: read `docs/graceful-shutdown.md`.
- A new Temporal workflow or activity: read `backend/workflowsdk/README.md`. A workflow registers itself in `init()` via `workflowsdk.MustRegisterWorkflow`; `task generate` runs `workflowgen`, which adds its import to the worker's `main.go`.

## Gotchas

- `ent/gen/`, `model/*_gen.go` and any file with a `Code generated` header are regenerated by `task generate`; edit the schema or the generator input instead.
- `TenantMixin`'s privacy policy scopes every query and mutation to the request's tenants, but skips the system user (`authn.SystemUser()`): code running as the system user must filter `tenant_id` itself.
- `HistoryMixin` hides rows with `deleted_at` set (unless `FEATURE_SHOW_DELETED`), but `Delete()` still hard-deletes: soft-delete with `SetDeletedAt`.
- New entity schemas default their `id` to `uuidgql.GenerateV7UUID` (time-ordered UUID v7); keep that default.
- Temporal workflow structs hold no state (one instance per worker); activities may hold clients. `workflowsdk` sets default activity options (10m start-to-close, retries); a custom `workflow.ActivityOptions` replaces all of them, so set the timeout and retry policy yourself.
- Rulesets match required checks by job name: renaming a job or matrix entry in `.github/workflows/`, including the gates `ci-success`, `build-success` and `deploy-success`, blocks every merge until the ruleset is updated.
- Short real-time TTL or ticker assertions in tests belong in a `testing/synctest` bubble; the self-hosted runner stalls for seconds.
